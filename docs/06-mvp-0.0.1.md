# MVP 0.0.1

MVP `0.0.1` is the first working slice of Demiurge. It intentionally implements
only the browser-side file router, but it uses the public vocabulary we want the
framework to grow into.

## Implemented

- Framework source split across `src/route`, `src/router`, and `src/browser`.
- Root public API exported from `src/index.ts`.
- Test-only internals exported from `src/internal/testing.ts`.
- Basic blog fixture app in `examples/basic-blog`.
- File discovery with `import.meta.glob`.
- URL matching from an app's `routes` folder.
- `index.tsx` routes.
- Dynamic path segments with `[slug].tsx`.
- Catchall segment parsing with `[...path].tsx`.
- Nested framework-attached layouts with `@layout.tsx`.
- Capability-based page routes with `GET = page(...)`.
- HTTP response capabilities with `json`, `text`, `html`, `redirect`,
  `notFound`, and `response`.
- `toResponse(...)` conversion for future HTTP runtime work.
- `createRequestHandler(...)` for non-page HTTP route capabilities.
- Client-side `<Link />` navigation.
- Browser back/forward handling.
- `path` dynamic path variables.
- `layout: false` page capability escape hatch.
- App-provided loading and not-found fallbacks for the browser router.
- Unit tests for route matching, layout inheritance, and page capability loading.

## Public Shape

Apps import from the framework package:

```tsx
import { page } from "demiurge";

export const GET = page({
  view: HomePage,
});

function HomePage() {
  return <h1>Hello</h1>;
}
```

Layouts are framework-attached files:

```tsx
// examples/basic-blog/src/routes/@layout.tsx
import type { LayoutProps } from "demiurge";

export default function RootLayout({ children }: LayoutProps) {
  return <>{children}</>;
}
```

Dynamic path values use `path`:

```tsx
export const GET = page({
  view: ({ path }) => <Post slug={path.slug} />,
});
```

Framework tests may import explicit internals:

```ts
import { unstable_createRouteManifest } from "demiurge/internal/testing";
```

## Not Implemented Yet

- Dev server integration for the HTTP request handler.
- Server rendering.
- React Server Components.
- SSE/file/download/stream response helpers.
- Typed generated route manifest.
- Typed `path` inference from filenames.
- Middleware.
- Policies and security headers.
- Strict CSP and nonce/hash pipeline.
- Metadata and document planning.
- Static generation.
- Cache adapters.
- Actions/mutations.
- Image/font/script optimization.
- Analytics integrations.
- Devtools/audit UI.

These are documented in the roadmap and feature inventory so the next slices are
clear.

## Framework Non-Opinions

The framework should not force fallback markup, CSS classes, copy, or page
structure. MVP `0.0.1` lets the example app provide `loading` and `notFound`
components to `createFileRouter`; future routing work should discover inherited
`@loading.tsx`, `@not-found.tsx`, and `@error.tsx` files from the app route tree.

## Next Implementation Slice

Build typed route context and route manifest generation:

```tsx
<Link to={routes.blog.post({ slug })}>Read</Link>
```

and:

```tsx
view: ({ path }) => {
  path.slug;
}
```

where `slug` is inferred from `routes/blog/[slug].tsx`.
