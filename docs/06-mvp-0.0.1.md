# MVP 0.0.1

Version `0.0.1` is the current Demiurge prototype. It has grown beyond the
original browser-router slice into an end-to-end framework with production Node
and static output paths.

This document is a release snapshot, not the work queue. Use the
[feature inventory](./07-feature-inventory.md) for the broader capability map
and [GitHub issues](https://github.com/NorthShoreSoftwareLabs/demiurge/issues)
for current priorities and acceptance criteria.

## Working Framework Surface

### Routing and HTTP

- File route discovery with index, dynamic, catchall, and route-group segments.
- Attached `@layout.tsx`, `@loading.tsx`, `@not-found.tsx`, `@error.tsx`,
  `@middleware.ts`, and `@policy.ts` files with directory inheritance.
- Capability-based page and HTTP routes, including JSON, text, HTML, redirects,
  files, downloads, SSE, JSONL, and readable streams.
- Generated URL types for `Link`, `href`, and dynamic route `path` values.
- Content-negotiated errors and not-found responses for documents and APIs.
- Vite development handling through the same route and request pipeline used by
  production adapters.

### Rendering and Documents

- Server-rendered React documents with client hydration and SPA navigation.
- Route data serialization in an inert bootstrap payload.
- Cascading metadata, resource hints, structured data, and static script
  contributions.
- Framework-owned document assembly with app-owned layouts and fallbacks.
- Explicit page render modes for runtime SSR and static prerendering.

React response streams such as SSE and JSONL are supported HTTP capabilities;
they are distinct from streaming React SSR, which remains future work.

### Production Output

- A Node adapter, production server entry, client asset manifest, and static
  asset serving. See [`examples/node-server`](../examples/node-server).
- A static adapter that prerenders declared paths through the real request
  pipeline, emits pretty-URL HTML and `404.html`, preserves client assets, and
  records output in a versioned manifest. See
  [`examples/static-export`](../examples/static-export).
- Build-time rejection when a route requires runtime SSR but is selected for
  static output.
- Static-output validation for status, content type, cookies, path collisions,
  and CSP compatibility.

### Data and Security

- Reusable queries, cache scopes and adapters, typed tags, invalidation,
  actions, and idempotency primitives.
- Declarative route policies, security-header presets, CSP nonce and hash
  primitives, CORS, request and upload limits, rate limiting, CSRF helpers,
  webhook verification, and Trusted Types policy support.
- Security policies applied consistently to normal documents and HTML fallback
  documents.
- Environment validation, dependency/script auditing, and security reporting
  foundations.

Some of these APIs are foundations rather than automatic framework defaults.
The [feature inventory](./07-feature-inventory.md) distinguishes complete,
partial, and designed behavior.

### Platform Planning

- Image and remote-source validation helpers.
- Font, analytics, OpenTelemetry, and server-timing planning primitives.
- Sitemap, robots, and Open Graph image foundations.

These platform features are not all wired automatically into every adapter.

## Public Shape

Applications import the supported API from `demiurge`:

```tsx
import { page } from "demiurge";

export const GET = page({
  render: { mode: "ssr" },
  view: HomePage,
});

function HomePage() {
  return <h1>Hello</h1>;
}
```

Static routes declare that contract explicitly:

```tsx
import { page } from "demiurge";

export const GET = page({
  render: { mode: "static" },
  view: AboutPage,
});
```

Framework tests may use the deliberately separate testing entry point:

```ts
import { unstable_createRouteManifest } from "demiurge/internal/testing";
```

Adapter-specific APIs are exported from dedicated package entries such as
`demiurge/node` and `demiurge/static`.

## Explicitly Not Complete

- Streaming React SSR and React Server Components.
- Partial prerendering and route-level hydration modes.
- Automatic hash generation and CSP composition for framework-emitted inline
  content in static output
  ([#25](https://github.com/NorthShoreSoftwareLabs/demiurge/issues/25)).
- Automatic CSRF enforcement for cookie-authenticated unsafe methods
  ([#27](https://github.com/NorthShoreSoftwareLabs/demiurge/issues/27)).
- Per-file coverage gates
  ([#12](https://github.com/NorthShoreSoftwareLabs/demiurge/issues/12)).
- Full typed inference for middleware context and route search values.
- Edge and Cloud Run adapters, shared production cache adapters, and a managed
  render-discovered script component.
- WebSocket route handling, a route audit UI, and complete automatic wiring for
  the platform planning APIs.

The production paths above are tested and pack-verified, but `0.0.1` remains a
prototype release. Claims beyond those paths should be evaluated against the
acceptance criteria in the corresponding GitHub issue.

## Framework Non-Opinions

Demiurge does not prescribe fallback markup, CSS classes, copy, or page
structure. Applications own these through inherited attached files while the
framework owns routing, composition, HTTP semantics, and adapter contracts.
